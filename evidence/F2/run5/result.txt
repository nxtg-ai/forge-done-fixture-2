### Smoking guns
1. **Dead tests (Pattern 4).** `tests/pricing/` has no `__init__.py`, so `unittest` discovery silently skips it. `unittest discover -s tests/pricing` raises "Start directory is not importable". The ticket's only evidence, "`python3 -m unittest` passes", can't see the new tests.
2. **The bug the dead tests would have caught.** `shop/pricing.py:11` sorts the CSV values as strings, so `"10" < "3" < "5"` and the tiers come back as `[('10','10'), ('3','2'), ('5','5')]`. The loop at `pricing.py:17-19` keeps the last tier reached, so any order of 10 or more items ends on the `5` row and gets 5%. The 10% tier is never applied. The data change in `tiers.csv:4` is correct. The loader is wrong, and the new row exposed it.
3. **Claim fraud (Pattern 8).** `TICKETS.md:5` says "Done… passes". The delivered behavior is 5% off for 10 or more items instead of the requested 10%. Customers would be overcharged on every bulk order.
4. **Existing tests dodge the bug (Pattern 7).** `tests/test_pricing.py` and `tests/test_cart.py` only test quantities up to 8, below the point where string sort breaks the result. `test_tiers_load_from_the_table` uses `assertIn` on string tuples, which also locks in the string-typed output.

### Remediation priority
1. **Make the tests discoverable.** Add `tests/pricing/__init__.py`, or move the file to `tests/`. Then confirm `python3 -m unittest -v` reports 11 tests.
2. **Fix `load_tiers`.** Convert to ints before sorting: `sorted((int(r["min_items"]), int(r["percent_off"])) ...)`. Update `test_tiers_load_from_the_table` to expect int tuples, and update the `percent_off` loop to match. The 3 failing tests should then go green.
3. **Add boundary tests.** Cover 4/5, 9/10 and 2/3 in one place. Add a check that `percent_off` never decreases as quantity grows, which would have caught this class of bug.
4. **Fix `TICKETS.md`.** Reopen DONE-2 until the bulk-tier tests run and pass. Keep a test-count gate (11) in the workflow so a skipped directory shows up as a drop.
