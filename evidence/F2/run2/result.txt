### Smoking guns
1. **Dead tests.** `tests/pricing/` has no `__init__.py`, so `unittest` discovery skips it. The `tests/` directory has one, which is why the other files are found. `tests/pricing/test_bulk_tier.py` is the only test file for the ticket, and it never runs.
2. **The feature is broken.** `shop/pricing.py:11` sorts `(row["min_items"], row["percent_off"])` as strings. That gives `[('10','10'), ('3','2'), ('5','5')]`, so `"10"` sorts before `"3"`. The loop in `percent_off` keeps the last tier it reaches, which is now the 5% tier.
   - `percent_off(10)`, `percent_off(12)` and `percent_off(25)` all return **5, not 10**.
   - `order_total(250, 12)` returns **2850**, but the bulk test expects 2700.
   - Customers ordering 10 or more items are being undercharged on the discount.
3. **The ticket claim is false.** `TICKETS.md:5` says "`python3 -m unittest` passes". That's true, but only because the new tests aren't collected.
4. **Existing tests can't catch it.** `tests/test_pricing.py` and `tests/test_cart.py` only exercise tiers 3 and 5. A single-digit-only fixture hides the string-sort bug, because lexicographic and numeric order agree for those values.
