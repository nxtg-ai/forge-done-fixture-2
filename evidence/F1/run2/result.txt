## The main finding: DONE-2 is not actually done

`TICKETS.md` says DONE-2 is done and `python3 -m unittest` passes. Both claims are wrong.

**CRITICAL 1: The bulk-tier tests never run.**
- `python3 -m unittest` runs 7 tests, but the repo has 11.
- `tests/pricing/` has no `__init__.py`, so discovery skips `tests/pricing/test_bulk_tier.py`. The 4 tests in that file are silently dropped.
- Run directly (`python3 -m unittest tests.pricing.test_bulk_tier`), 3 of the 4 fail.

**CRITICAL 2: The 10% tier doesn't work.**
- `load_tiers()` in `shop/pricing.py:11` sorts the CSV values as strings.
- The order comes out `('10','10'), ('3','2'), ('5','5')`, because `"10"` sorts before `"3"`.
- `percent_off` keeps the last tier the quantity reaches, so the 5% tier overrides the 10% one.
- Actual output: `percent_off(10)`, `percent_off(12)` and `percent_off(25)` all return 5, not 10.
- `order_total(250, 12)` returns 2850 instead of 2700, so customers are overcharged on every bulk order.
- The docstring says "smallest tier first", which is false.

The first problem hid the second: the suite looks green only because the tests that would catch the bug aren't collected.
